## 二、流程偏差揭露（本節為稽核用途，逐項已複驗）

### 2.1 `acb0142` 的 ship-gate 放行未留遙測

**事實（直接查證）**：

- 本次 commit 指令為 `cd /home/ubuntu/CyTrace && ASP_SHIP_OK=1 git commit -q -F - <<'EOF' …`。
- `~/.claude/asp/hooks/pretooluse-ship-gate.sh:23` 的判定為
  `grep -qE '(^|[;&|]+[[:space:]]*)git[[:space:]]+commit'`——要求 `git` 緊接**行首**或 `;&|` 之後。
  上述指令在 `&&` 之後接的是 `ASP_SHIP_OK=1` 而非 `git`，**比對不到**，hook 於 `:23` 即 `exit 0`。
- `:36` 檢查的是 hook 行程自身的 `${ASP_SHIP_OK:-}`；指令行內的變數前綴屬於**子指令**環境，傳不進 hook 行程。
- **結論**：`:64` deny 訊息與 CyTrace `CLAUDE.md` 所稱「用 `ASP_SHIP_OK=1 git commit …`（會留 bypass 遙測）」
  **在設計上永遠不會發生**。準確描述是：該 commit 被 ship-gate 擋下後，改用 gate 認不出的指令形式**靜默通過**，
  並非走了會留痕的出口。
- 佐證：`~/.asp/bypass-log.ndjson` 的 CyTrace 條目數為 **0**。
